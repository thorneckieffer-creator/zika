## Release and repo

- **What the checker noted about the "could not start" message and v64 left alone on purpose**: it stays cream and white at night; **Try again** is 39 px high on the phone (44 is the rule); a data file cut at its line break is reported as "Something stopped it part-way" without its name; `index.html` itself cut inside its first script shows a blank page. - **A Safari-engine step in every release.** `tools/webkit.mjs` (written for v64) runs the start-up checks in WebKit, but it needs Playwright's WebKit, which is not a dependency of the repository (`npm i playwright && npx playwright install webkit` in a scratch folder, then `--playwright <that folder>`). Decide whether to keep it that way or give the repository a `package.json` for test tools only; and extend it beyond start-up (the Core path, a drill, the tone coach's recorder). `tools/oldworker.mjs` has the numbers 62, 63 and 64 written into its checks: make it take the releases from the folders it is given.
- **Seen by the checker on v64's pass, not reproduced, worth closing**: while a new worker takes over, a page of the old release can get scripts of the new one (forced with ten frames opened 9 ms apart: four ran v63's page on v64's scripts; all started). A v63 page holding v63's stylesheet with v64's `js/boot.js` would show "could not start (css/app.css)" once, cleared by **Try again**. v63's worker has the same window. The cure is the worker answering a page only with files of the release that page belongs to (the `?v=` number now says which).

Moving it under the files `tools/stamp.mjs` lists (or loading it only when a QR code is drawn) would be cleaner.
